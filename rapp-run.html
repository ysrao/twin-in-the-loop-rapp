Step 3 — Select the function, hand the run to the twin

Run exactly what is chosen above (mode, tower, counters per tower, function) on either:

Run on my Mac Run on Colab

Mac — Sionna RT on your Mac's GPU (Apple silicon), from a clone of the repository. Start the local runner first: in the clone, run .venv/bin/python local/rapp_server.py (one-time setup in the README). Then press the button: the run starts by itself in a new tab and the result shows there. If that tab says it cannot connect, the runner is not running.
Colab — Google's GPU, nothing to install. The button copies this run's package and opens the notebook. In Colab, click the package cell (the one that starts PACKAGE_JSON), select all (Cmd/Ctrl+A), paste, then Runtime → Run all. The result prints in the last cell.

If no tab opened: then paste it into a new browser tab.

Step 4 — The result: changes and improvement

Load the result file from the run:

Recommended changes

How the run works, honestly. The optimisation itself — the ray-traced twin, the SYS link curve and slice environment, the guarded search, the audit's histogram fit — is the prototypes' own code, and it runs in the notebook (Sionna RT + SYS), not in this page: a static page cannot ray-trace. This page prepares the run from the sites and the counter dump and presents what the twin verified. Nothing is emitted unless it passes the twin gate; a run that finds nothing worth changing says so and keeps the as-built configuration.
