Step 3 — Select the function, hand the run to the twin

2 · Open the runner notebook (Colab)

Or skip this page entirely: the runner notebook stands alone — change MODE and FUNCTION at its top and Run all; the study network is built in. This page is the advanced path: the box below is the run package for the mode, function, sites and counters above, rebuilt whenever you change anything. Copy it, and in the notebook paste it over the whole package cell (click the cell, select all with Cmd/Ctrl+A, paste) — a pasted package overrides the notebook's own settings. Then Run all: the runner traces the twin with Sionna RT, scores with Sionna SYS, evaluates the existing configuration from the counter dump, runs the optimisation, and applies the twin gate. The result prints in the notebook's last cell — the changes, the before → after numbers and the maps. No files, no downloads.

How the run works, honestly. The optimisation itself — the ray-traced twin, the SYS link curve and slice environment, the guarded search, the audit's histogram fit — is the prototypes' own code, and it runs in the notebook (Sionna RT + SYS), not in this page: a static page cannot ray-trace. This page prepares the run package from the sites and the counter dump; the notebook runs it and its last cell presents what the twin verified. Nothing is emitted unless it passes the twin gate; a run that finds nothing worth changing says so and keeps the as-built configuration.
